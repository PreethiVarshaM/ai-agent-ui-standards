# Responsive design

- Follow the project's responsive patterns and breakpoints. Add or change breakpoints only when the content or interaction requires a layout change.
- Design for available space and content needs rather than a list of specific device models.
- Keep reading order meaningful across layouts. Visual rearrangement must not make keyboard or screen-reader order confusing.
- Prevent unintended horizontal scrolling, clipped controls, overlapping content, and text truncation that hides necessary information.
- Allow long labels, localized text, validation messages, and user-generated content to grow or wrap.
- Adapt navigation, columns, density, and controls while preserving access to the same essential content and actions.
- Support touch-sized interaction areas consistent with project requirements, while keeping pointer and keyboard use functional.
- Check narrow, intermediate, and wide viewports, plus zoom or text enlargement where practical.
